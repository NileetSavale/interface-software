The idea

One expensive, careful run. Then free, boring, exact ones.

The model's judgment is needed once per task, so spend it there and nowhere else. Everything after discovery is a contract a reviewer can read and a machine can check.

Keeping up with the field

The perception model was chosen against what shipped weeks ago, not what was standard a year ago.

OCT302026
Vercel Labs · agent-desktop v1.0.2

Computer use through the OS accessibility tree instead of pixels: a ref on every actionable element, clicks that go through the accessibility API "without moving the pointer or taking focus", refs that belong to their snapshot and fail loudly as STALE_REF / AMBIGUOUS_TARGET. (Write-up on dev.to, Nov 2.)

What we did with it: explored it during design, two weeks after release, and adopted its perception model: tree snapshot → act on a ref → observe again, with a retry disposition on every error. We built it in-process on Playwright for the browser, and our surface interface is the seam where an agent-desktop-style native surface plugs in. Its stated limit, that an app with no accessibility tree is invisible, is why bounding-box strategies stay in the schema for desktop surfaces.

  • Claude 5.5's thinking binding. Current models bind their thinking to the exact conversation, so trimming old snapshots client-side would break it. Switched to server-side context editing; history stays append-only. Caught by reading the current API docs, and the AI corrected its own locked design (D17).
  • Server-side model fallback and a mid-run Sonnet → Opus switch on the same conversation, so escalation never rewrites history.
  • Playwright's AI snapshot mode: refs that work across legacy framesets, so the model clicks by ref and replay never sees one.
